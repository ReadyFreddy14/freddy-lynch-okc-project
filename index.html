What makes a shot more likely to go in?

A model that estimates the chance of a made basket using shot location, shot type, player identity and defender tracking.

Freddy Lynch · Python / CatBoost · Supplied data only

The project in plain English

The goal is to assign each test shot a probability between 0 and 1. For example, a prediction of 0.70 means an estimated 70% chance of making the shot. It does not guarantee that the individual shot will go in.

The model is CatBoost, which combines many small decision trees. Each tree learns patterns such as how shot distance, shot type and defensive pressure work together. CatBoost can also use categories such as shooter IDs without treating those IDs as numerical measurements.

Why hold out a season? The training data cover two seasons, while the test data cover a different season. To check performance across seasons, the model first learns from one training season and predicts the other.

Season fe055 supplies 213,261 validation shots. It is selected by sorting the season IDs and taking the last one. These IDs do not reveal dates, so this checks transfer between seasons without claiming which season came first.

How the code works, step by step

  1. Load and check the files. main() reads the compressed training and testing files directly. It checks that shot IDs are unique, train and test IDs do not overlap, and the submission template matches the test shots in order.
  2. Prepare the features. binary() converts true/false values to 1/0. features() removes the outcome and shot ID from the predictors, splits the four defender-approach distances into separate columns, and handles missing categories.
  3. Add a few useful measurements. The code measures how far the defender closes over one second and their closing speed in the final quarter-second. It also adds absolute court coordinates, a no-dribble indicator and an indicator for four seconds or less on the shot clock. These calculations use the shot's inputs, not its outcome.
  4. Train and validate. CatBoost learns from one season. The other season is used to calculate validation log loss and choose when to stop adding trees. Two simpler models provide comparison points.
  5. Explain the results. score() calculates the metrics below. report() creates the feature-importance chart, calibration chart and this writeup.
  6. Fit the final model and save predictions. The model is trained again using all 425,719 labeled shots and the selected 357 trees. Its predictions fill make_prob in submission.csv. The original shot IDs, row order and column names are preserved.
Model settings and missing data

The run allows up to 650 trees, with depth 6, learning rate 0.05, L2 regularization 8 and random seed 42. Training stops after 80 rounds without better validation log loss. Missing category values receive a label; missing numerical values are handled by CatBoost. An absent contester is not treated as a defender standing zero feet away. CatBoost learns its category statistics from the fit data, not the validation outcomes.

  • Constant: gives every validation shot the same probability: the made-shot rate in the fit season.
  • Shot type: uses a different fit-season make rate for each shot type, with 20 pseudo-observations at the overall rate to stabilize small groups.
  • CatBoost: uses the wider set of shot and tracking features. It ranks shots better by AUC, while the shot-type baseline has lower log loss and Brier score in this held-out season.

Log loss penalizes incorrect probabilities, especially confident mistakes. Brier score measures the average squared gap between probability and the 0/1 outcome. Lower is better for both. AUC measures how well the model ranks made shots above missed shots; 0.5 is chance ranking and 1.0 is perfect ranking. An AUC of 0.674 does not mean 67.4% accuracy.

These scores use actual shot outcomes. The project's private evaluator instead compares predictions with its own model's probabilities. This validation score cannot tell us the private evaluator's score.

Which features matter most?

In the validation-fit model, the strongest features are shot distance, shot type and nearest-defender distance. Shooter speed and first-contester distance also contribute. Importance measures how much the model uses a feature; it does not prove a cause or show the direction of an effect.

What could be improved?

This run compares two baselines and one CatBoost configuration. It does not include a broad search for the best settings. The validation season also selects the tree count, so its score is not an untouched final test result.

  • Test the season split in reverse. This would show whether the result holds when the two training seasons switch roles.
  • Check which feature groups help. Remove groups of inputs and compare results, especially related defensive measurements.
  • Investigate calibration. Use a separate split to test whether adjusting the probabilities improves their agreement with make rates.
  • Handle limited player history. There are 1,146 test shots from shooters absent in training. Their IDs provide no learned player-specific history.

Tracking noise and changes between seasons remain limitations. If extra data were permitted, game dates, fatigue measures, release mechanics and longer player histories could be useful. No external data were used in this project.

Run the project and review the work

With the packages in requirements.txt installed, run python project_code.py. This regenerates the predictions, metrics, charts and report. The saved results are in metrics.json; supporting chart values are in feature_importance.csv and calibration.csv.

The probability calculation

Base chance = (nearby makes + 25 × league local rate + 35 × player shot-type rate) / (nearby attempts + 60). A local sample includes shots within 5 feet and the same 2P/3P classification. Recorded shot coordinates are used to classify local attempts as 2P or 3P; positions very close to the line can be ambiguous. The player shot-type rate is smoothed with 30 league-average attempts; the league local rate is smoothed with 50 shot-type-average attempts.

Defense rates are stabilized with 300 league-average minutes. A heuristic modifier uses 0.008 × blocks/36 above league average and 0.003 × steals/36 above league average, capped at ±0.04. It is scaled by pressure (0, 0.7 or 1.3); the pressure setting also adds +0.04, 0 or −0.07. Beyond 35 feet, both the base chance and the adjustment are multiplied by exp(−(distance − 35) / 14). The final probability is limited to 0.01–0.95.

Limits of the data

No exact shooter-versus-defender tracking is available here. Blocks and steals are imperfect defensive proxies, not a measured effect on shooting percentage. The modifier and smoothing choices have not been validated as a predictive model. For shots beyond 35 feet, a clearly labeled exponential distance penalty extrapolates toward a 1% floor; there may be few or no recorded attempts nearby.

Shots are independent random draws. The animation illustrates the result; the hold-and-release meter adds a gameplay timing adjustment, and close contests apply a small extra penalty. There is no foul or free-throw simulation.
